# Проєкт: Мій помічник у дієті (моя дієта)

## 1. Загальний опис та мета
Додаток для полегшення дотримання дієти для мого сина (має ФКУ — фенілкетонурію). 
* **Основна мета:** ведення архіву записів спожитих продуктів/страв та відображення кількості калорій, фенілаланіну (ФА), води та інших нутрієнтів для контролю показників крові.
* **Масштабування:** додаток створюється корисним і для людей з іншими орфанними та хронічними захворюваннями, де строга чи помірна дієта є запорукою фізичного та психічного здоров'я.

## 2. Структура проєкту (lib/)
* **Головний файл:** `main.dart`
* **Екрани (screens):** 
  * `splash_screen.dart` — Екран заставки (splash з логотипом `splash_logo_widget.dart`).
  * `main_screen.dart` — Головний робочий екран (каркас з верхньою панеллю та правим виринаючим меню).

## 3. Бази даних та структури (у розробці)
1. *Академічна база:* перевірені дані по базових продуктах (овочі, фрукти тощо) від дослідницьких інститутів.
2. *База готових продуктів:* фабричні товари, етикетки (випічка, солодощі, сири тощо).
3. *Мої страви (користувацькі рецепти):* власні рецепти з підрахунком нутрієнтів на 100 г готової страви, з відстеженням залишків для розуміння потреби готувати знову.
4. *Динамічна база наявних продуктів:* напівфабрикати та залишки для майбутньої функції генерації порад «що приготувати з того, що є вдома».

## 4. Інтеграція кастомного календаря та української локалізації (13.08.2026)
- **Локалізація `intl`**: Успішно підключено пакет `intl` та додано ініціалізацію `initializeDateFormatting('uk_UA', null)` у функцію `main()` для підтримки української мови.
- **Спільний віджет календаря (`CalendarWidget`)**: Реалізовано зручний віджет перемикання днів із дворядковим виводом дати та клікабельним центром для виклику кастомного діалогу вибору дати.
- **Виправлення відмінків**: Налаштовано відображення днів тижня у називному відмінку (Понеділок, Вівторок, Середа тощо) замість стандартного для бібліотеки родового відмінка.

## 5. Візуальна індикація критичних показників та норм (13.08.2026)
- **Двоциклові прогрес-бари**: Реалізовано просунуту логіку відображення для критичних нутрієнтів (ФА, білок, калорії тощо) у віджеті `DailySummaryWidget`.
- **Перший цикл (0% — 100%)**: Стандартне заповнення у фірмовому кольорі нутрієнта в межах дозволеної норми.
- **Другий цикл (Перевищення > 100%)**: Автоматичне перемикання смужки у тривожний червоний колір і повторне заповнення (від 0% до 100%) для наочного відображення масштабу перебору.
- **Динамічний розрахунок кратності**: При перевищенні ліміту під смужкою автоматично з'являється числовий підпис (наприклад, «Перевищення у 2.3 раза!»).
- **Глобальні сповіщення**: Впроваджено загальну систему інформування — якщо хоча б один критичний показник виходить за червону межу, на початку віджета виводиться попереджувальний блок.

## 6. Адаптивність та розгортання карток зведеного віджета (14.08.2026)

- **Захист від нескінченності (`Infinity`)**: Додано перевірку `constraints.hasBoundedHeight` для запобігання помилкам рендерингу у разі відсутності жорстких обмежень висоти від батьківського контейнера.
- **Інтерактивне згортання/розгортання**: Реалізовано плавне перемикання між адаптивною кількістю карток та їх повним списком за допомогою кнопки «Показати всі» / «Згорнути».

Моделі (models) — це структура даних (шаблон або «республікація» об'єкта). Вони не виконують жодної бізнес-логіки і не знають про те, як дані зберігаються чи завантажуються. Модель просто описує, з яких полів складається об'єкт (наприклад, ProductModel має назву, категорію, кількість білків, жирів, вуглеводів тощо) і як перетворювати його в JSON для збереження.

Сервіси (services) — це «робочі конячки», які виконують конкретні операції, взаємодіють із зовнішнім середовищем або надають готову функціональність. Це може бути робота з локальним сховищем, мережевими запитами, шифруванням, звуком або специфічними розрахунками (наприклад, сервіс приготування страв чи підрахунку нутрієнтів).

Репозиторії (repositories) — це посередники (шаблон Repository Pattern) між вашим інтерфейсом (екранами) та джерелом даних. Репозиторій вирішує звідки взяти дані (з локального файлу, бази даних SQLite, пам'яті чи хмари) і куди їх зберегти, приховуючи від екранів усю технічну складність роботи зі сховищем.

Утиліти (utils) — це допоміжні, ізольовані інструменти («чисті функції»), які не прив'язані до стану якогось конкретного екрана чи бази. Вони приймають якісь вхідні дані, щось із ними роблять (як наш ProductSearchHelper для фільтрації та сортування) і повертають результат. Їх можна легко викликати з будь-якого місця програми.
